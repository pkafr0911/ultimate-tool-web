# Photo editor control and regression matrix

Date: 2026-10-14. Status labels describe behavior, not merely presence of handlers. **WORKING** means the stated path has automated behavioral evidence; **PARTIALLY WORKING** means implemented but incomplete or not exhaustively verified; **BROKEN** means a known failing path; **NOT IMPLEMENTED** means absent/unmounted. Controls grouped in a row share implementation, but coverage limits remain explicit.

Tests: `O` = `opencv.test.ts` native-resource cleanup with mocks; `U` = `document.test.ts` geometry/persistence/color tests; `H` = `history.test.tsx` React hook integration; `B` = `tests/photo-editor/browser.cjs`, real headless Chrome at DPR 2 against a production build. Browser tests use actual file inputs, keys, sliders, pointer strokes, dialogs and exports. Scene reads and selected setup operations use the live Fabric instance via a test-only React fiber traversal; no debug API is added to production. Downloads are intercepted at anchor activation, decoded and checked; the OS download destination is not tested.

## Commands and interpretation

- `npm run test:photo-editor`: focused Jest geometry/state/color suite, independent of Umi setup. Raster APIs are not mocked into a false success claim.
- `npm run tsc`: repository TypeScript check.
- `npm run build` and `npm run build-pre`: ordinary and GitHub Pages production builds.
- `PORT=8124 node tests/photo-editor/serve.cjs`, then `EDITOR_URL=http://127.0.0.1:8124/ultimate-tool-web/visual-tools/photo-editor npm run test:photo-editor:browser`.
- Browser executable defaults to `/usr/bin/google-chrome`; override `CHROME_PATH`. The repository already carried Puppeteer Core 1.12.2 transitively; it is now an explicit test dependency. A future test-runner update is recommended separately.

See `../reports/PHOTO_EDITOR_ENGINEERING_REPORT.md` for the final commands/results. Test coverage is representative rather than certification of every control above.
